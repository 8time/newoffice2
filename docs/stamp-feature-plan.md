# スタンプ機能 実装指示書（Opus向け）

LINE風の「動くスタンプ」をチャットで使えるようにする。
まず**スタンプメーカー**（自分たちでスタンプを登録できる仕組み）を作り、その上に送信・表示を載せる。
参考イメージ: LINEスタンプのような、背景透過でキャラクターが動く画像（クマ・ウサギ等）。

**着手前に必ず `POST /api/backups/now` を叩いてバックアップを取ること。**

---

## 全体像とフェーズ分け

| フェーズ | 内容 | 優先度 |
|---|---|---|
| 1 | 表示ルールの分離（絵文字/スタンプ単体送信は「スタンプモード」で大きく） | 必須・独立して先行可 |
| 2 | スタンプメーカー（設定ダイアログ内。登録・一覧・削除） | 必須 |
| 3 | チャットからのスタンプ送信 | 必須 |
| 4 | お気に入り・使用回数順 | 任意 |
| 5 | マップ上の頭上スタンプ演出 | 任意 |

フェーズごとにE2E→コミット→push。一気に作らない。

## フェーズ1: 表示ルールの分離（スタンプモード）

**チャットのメッセージを2種類のレンダリングに分ける。**

- **通常メッセージ**: 今までどおり吹き出しあり（現在のデザインを一切変えないこと）
- **スタンプメッセージ**: 吹き出しなし・背景透明・大きく表示

### 判定ルール

メッセージ本文が**絵文字のみ**（文字を1文字も含まない）ならスタンプモード。

- 「👍」「😊🙏」 → スタンプモード
- 「了解👍」「ありがとう😊」 → 通常（現在と同じ）
- 判定は `Extended_Pictographic` のUnicodeプロパティ＋ZWJ・異体字セレクタ・肌色修飾を許容する正規表現で行う。絵文字3個までをスタンプモードとし、4個以上は通常表示（Discordと同様の感覚）

### 表示仕様

- 絵文字単体: フォントサイズを通常(18px)の約3.5倍（**64px程度**）
- 吹き出し（`Bubble`）と、そのしっぽ(`::before`)を出さない。背景・影なし
- 既読数・時刻のメタ表示は今までどおり出す
- 実装箇所: [Chat.tsx](../client/src/components/Chat.tsx) の `Message` コンポーネント。`messageType === FILE_MESSAGE` の分岐が既にあるので、その並びに「スタンプモード」の分岐を足す形にする

## フェーズ2: スタンプメーカー（設定の中）

**置き場所は設定ダイアログ**（[SettingsDialog.tsx](../client/src/components/SettingsDialog.tsx)）。
MAP下部メニューの「設定」→「スタンプ」セクションを追加する。設定ダイアログは maxWidth="xs" で狭いので、セクション内には「スタンプを管理」ボタンだけ置き、押すと専用の管理ダイアログを開く構成でよい。

### 管理ダイアログの機能（MVP）

1. **登録**: 画像を選択 → 名前を入力 → カテゴリ選択（挨拶 / 仕事 / 感情 / その他）→ 保存
2. **一覧**: カテゴリごとに登録済みスタンプをグリッド表示（アニメはその場で動く）
3. **削除**: 自分が登録したものだけ削除できる（authorをclientIdで判定。サーバー側でも検証すること — 画面上の制限だけにしない）

### 対応形式と容量

- **PNG / GIF / WebP（アニメ含む）/ APNG** を受け付ける
- 1ファイル **最大1MB**。超えたら「スタンプは1MB以下にしてください」と表示して拒否
- 推奨サイズの案内を添える（例: 320×320px程度）

### ⚠️ 実装上の罠（必ず守る）

1. **スタンプ画像を `shrinkImageFile` / `shrinkDataUrl` に通さないこと。**
   [imageShrink.ts](../client/src/util/imageShrink.ts) の `SKIP_TYPES` はgif/svgしか除外しておらず、
   `createImageBitmap` は**アニメWebP/APNGの1コマ目しか読まない**。通すと動きが失われて静止画になる。
   スタンプのアップロードは縮小せず**原本のまま** `/api/files` へ送る（1MB上限があるので容量は問題ない）。
2. **アップロードは既存の `/api/files` を使う**（SHA-256重複排除・Supabase保存・使い回し時のcreated更新が全部付いてくる。新しいアップロード経路を作らない）。

### データ構造（サーバー）

`registerDoc('stamps', <ローカルはstamps.jsonへ>)` で共有レジストリを1つ持つ。

```jsonc
// doc "stamps"
{
  "stp_1700000000_abc": {
    "name": "ありがとうクマ",
    "category": "挨拶",           // 挨拶 | 仕事 | 感情 | その他
    "url": "/files/f_xxxx",       // 必ず /files/ 形式で持つ（下記の理由）
    "type": "image/webp",
    "author": "<clientId>",
    "authorName": "にゃっと",
    "useCount": 0,
    "createdAt": 1700000000000
  }
}
```

- **`url` は必ず `/files/f_xxx` の形で保存する。** [cleanup.ts](../server/cleanup.ts) の `collectReferencedFileIds()` は全ドキュメントから `/files/(f_...)` を正規表現で拾うため、この形で持っておけば**スタンプ画像は30日自動削除の対象から自動的に守られる**。別の形式（IDだけ等）で持つと守られず、30日後にスタンプが消える。
- 追加・削除はColyseusのメッセージ（`ADD_STAMP` / `REMOVE_STAMP` / `REQUEST_STAMPS` を `types/Messages.ts` の**enum末尾**に追加。途中に挿すと既存の番号が全部ずれて通信が壊れる）で行い、全クライアントへ反映する。
- **[backup.ts](../server/backup.ts) の `TARGETS` に `'stamps'` を追加**する（レジストリを誤って壊しても世代から戻せるように）。

## フェーズ3: チャットからのスタンプ送信

### UI

- チャット入力欄の絵文字ボタン（既存の emoji-mart Picker）の隣にスタンプボタンを追加
- 押すとカテゴリタブ付きのスタンプ一覧がポップアップ → クリックで即送信
- **現在のチャットデザインを崩さないこと**（入力欄・吹き出しの見た目は不変）

### 送信の仕組み（重要）

新しいメッセージ種別は作らず、**通常のチャットメッセージとして本文に `[stamp:stp_xxx]` というマーカーを入れて送る**。

理由: `ADD_CHAT_MESSAGE` の経路に乗せれば、**履歴の永続化・日付区切り・既読・送信取消（右クリック）が全部そのまま効く**。
`SEND_FILE_MESSAGE`（ファイル添付）は履歴に残らない設計なので使わない。

### 表示

- 描画側（`Message` / [ChatMessageContent.tsx](../client/src/components/ChatMessageContent.tsx)）で本文が `[stamp:...]` 単体ならスタンプモード:
  レジストリからURLを引いて `<img>` 表示（**最大160px**・吹き出しなし・背景透明）。GIF/アニメWebPはimgタグだけで勝手に動く
- レジストリに無いID（削除済み等）は「(削除されたスタンプ)」とテキスト表示で退避
- 送信時に `useCount` をインクリメント（フェーズ4の並び替えの布石）

## フェーズ5（任意）: マップ上の頭上スタンプ

既存のエモート経路（`SEND_EMOTE` → 頭上に絵文字表示）が既にあるので、それを拡張して
`emoji` の代わりに `stampId` も送れるようにし、アバター頭上に約2秒スタンプ画像を表示する。
新しい同期の仕組みを作らないこと。

## 制約・注意（全フェーズ共通）

1. **著作権**: LINE等の既存キャラクター画像を同梱しない。初期スタンプを入れる場合は自作の簡単なもの（丸顔+テキスト程度）のみ。基本はユーザーが自分でアップロードする前提でよい
2. **XSS**: スタンプ名は表示前にエスケープ（メモ欄のsanitizeと同じ思想。名前は最大30文字に制限）
3. **入力欄のキー**: 設定・管理ダイアログ内の入力は既存の `setupTypingGuard`（focusin監視）が面倒を見るので追加対応不要。ただし新しいダイアログでEnterが誤動作しないかはE2Eで確認する
4. **既存機能を壊さない**: チャットの通常メッセージ・ファイル添付・PDF/YouTubeプレビュー・送信取消の見た目と挙動は変えない

## 検証（必須。プロトコルだけのPASSは不可）

各フェーズで Playwright の実ブラウザE2E（`scripts/e2e-stamps.js` として作成、既存の `e2e-*.js` の書式に合わせて `[PASS]/[FAIL]` 出力・テストデータの後片付けまで行う）:

- フェーズ1: 「👍」単体→吹き出しなしで大きい / 「了解👍」→通常の吹き出し（スクリーンショットで目視確認も）
- フェーズ2: 登録→一覧に出る→**別ブラウザ（別コンテキスト）にも出る**→他人のスタンプは消せない（**サーバーへ直接削除要求しても拒否されること**）→1MB超は拒否→**アニメWebPを登録して動きが失われていないこと**（登録前後のファイルサイズ一致で判定）
- フェーズ3: 送信→相手の画面にスタンプモードで表示→リロード後も履歴に残る→送信取消で両者から消える
- 回帰: `e2e-chat.js` / `e2e-chat-unsend.js` / `e2e-chat-no-join.js` が全部PASSのまま
